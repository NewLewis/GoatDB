# Repository Guidelines

## Project Structure & Module Organization
- `src/`: Rust source code for the storage engine, gRPC server/client, and utilities.
- `tests/`: Integration and E2E tests (`tests/e2e/`, `tests/common/`, `tests/integration/`).
- `proto/`: gRPC service definition (`goatkv.proto`) compiled via `build.rs`.
- `docs/`: Architecture and format references (e.g., SSTable, skip list design).
- `scripts/`: Helper scripts for development tasks.
- `target/`: Build outputs (generated by Cargo).

## Build, Test, and Development Commands
- `cargo build --release`: Optimized release build.
- `cargo build --bin goatkv_server`: Build server binary only.
- `cargo run --bin goatkv_server`: Start the gRPC server locally.
- `cargo run --bin goatkv_client -- put key value`: Run one client command.
- `cargo test`: Run all unit, integration, and E2E tests.
- `cargo test --test e2e_basic_crud`: Run a specific E2E test.
- `cargo fmt`: Format code with rustfmt.
- `cargo clippy --all-targets --all-features -- -D warnings`: Lint with clippy.

## Coding Style & Naming Conventions
- Rust formatting: use `cargo fmt` (default rustfmt settings).
- Linting: `cargo clippy` with warnings treated as errors.
- Naming: follow Rust conventions (snake_case for functions/modules, CamelCase for types).
- File layout: keep core engine code under `src/goatkv/` with focused modules.

## Testing Guidelines
- Unit tests live alongside code in `#[cfg(test)]` modules.
- Integration utilities are in `tests/common/`.
- E2E tests are under `tests/e2e/` and registered in `Cargo.toml` `[[test]]` entries.
- Slow/load tests may be marked ignored; run with `cargo test -- --ignored`.

## Commit & Pull Request Guidelines
- Commit messages are short, imperative, and descriptive (e.g., “Add cleanup worker…”).
- PRs should include: a clear description, testing performed, and any relevant context.
- If behavior changes, add or update tests and note any new flags or configs.

## Security & Configuration Tips
- Default data directory is `./goatdb_data` (configurable via engine options).
- Protocol buffers compile automatically via `build.rs` using `tonic-prost-build`.
